# 界面设计规范

> 本文只回答一件事：**界面长什么样，内容为什么这样排。**
> 技术选型见 README；文件放哪见《项目目录结构说明》；云函数字段见《云函数接口文档》。
>
> 维护规则：**改界面前先改本文，再改 WXSS / WXML。** 新颜色、字号、圆角、组件先登记，不在页面里另造一套。
>
> 当前版本：**Daylight Console / 白昼控制台 v3.6.1**（2026-11-13，暖纸 / 深青 / 底部导航 / 全页面自定义导航栏 / tab 切换微动效 / 可选登录 / 设置页 / 注销账户 / 基础信息 + 核心属性 / 个人中心冰纹图腾 / 战力数字动效）。
> v1 是浅色卡片、v2 是深色皮肤；v3 明确把重点从「换配色」转到「按内容重组布局」：
> 页面不默认套一张大卡片，而是先判断内容角色，再选择开放页面、身份舞台、表单纸面或数据表。

---

## 一、设计基调

1. **结构先行，颜色靠后。**
   先决定信息分几块、谁是主视觉、哪里该留白；颜色只负责品牌和状态。
2. **开放页面 + 少量纸面。**
   身份、标题、进度、关键数字直接落在纸色页面上；只有表单和数据表才用白色纸面承托。
3. **用线分隔，不用卡片堆叠。**
   主要节奏来自 `1rpx` 墨线、分区编号和大留白；不是每个内容都包成圆角卡片。
4. **一个信号色。**
   深青只用于进度、编号、焦点、链接和少量状态；主操作是墨黑按钮。页面其余保持暖纸 + 墨色。
5. **大标题、短说明、清楚动作。**
   一页只回答一个问题；标题和主操作必须一眼可见，其他内容退到次级。
6. **动效是线性的、短的、有方向的。**
   入场、进度线、焦点、保存反馈；不做满屏粒子、漂浮、霓虹和持续旋转。

## 二、内容结构先行

### 2.1 启动：先浏览，后登录

- `app.json` 第一页是 `pages/overview/overview`（总览 tab），启动直接进入可浏览内容。
- 启动**不调用 `bootstrap()`**，不显示登录封面，不弹授权，不要求手机号 / 头像 / 昵称。
- 总览、拜访、同盟属于账号数据页，未登录时不伪造内容；页面保留但显示明确的登录后读取说明。
- 「我的」进入时判断登录状态：未登录直接 `reLaunch` 到登录页；登录页提供「先逛逛，不登录」返回总览。
- 退出登录 / 注销账户后回到总览；再次进入「我的」时判断状态并进入登录页。
- 只有用户主动点击「微信登录」才调用云函数识别微信身份；这是可选动作，不是启动前置条件。
- `pages/index/index` 登录页保留注册，但只作为普通非 tab 页面，从「我的」未登录时进入，不作为启动页。
- DevTools 最前面的白色帧来自工具启动画布，不属于小程序页面。

### 2.2 登录：从「我的」直接进入登录页

- 启动页仍是总览，不在启动时要求登录；
- 用户点击「我的」时判断状态：未登录直接 `reLaunch` 到登录页；
- 登录页保留「先逛逛，不登录」，给用户返回总览的选择；
- 点击「微信登录」后才发起 `bootstrap()`；
- 成功后的分流：
  - 已初始化角色 → 个人中心；
  - 未初始化角色 → 角色初始化页；
  - **不再自动进入微信头像 / 昵称页**；
- 微信头像 / 昵称只在资料不完整提示或设置页中由用户主动进入；
- 登录失败留在登录页并显示错误，不跳转、不重试循环；
- 不调用 `getPhoneNumber`，没有手机号授权步骤。

### 2.3 微信资料：可选完善，不是登录前置条件

- 微信资料页只从个人中心「去完善」或设置页「微信资料」进入，不能从登录流程自动进入。
- 页面仍保留头像 + 昵称结构，但用户可随时返回，未完善不阻塞使用。
- 头像昵称使用官方组件，由用户主动点击 / 输入；不做静默获取。
- 未完善时个人中心显示 inline banner，而不是强制跳转。

### 2.4 角色初始化：三项输入，分区填写

**内容角色**：游戏昵称、性别、总战力、组织说明。

**布局决定**：

- 顶部保留两步流程的完成态（100% 进度线）；
- 页面主体是一张 **分区表单**，不再放实时预览：
  - `01 基础身份`：游戏昵称 + 性别；
  - `02 战力指数`：总战力；
- 保存按钮只出现一次，放在表单末尾；
- 组织说明是左侧竖线的 note strip，不参与表单；
- 宽屏保持单列表单，不为了填满屏幕而拆左右栏。

表单本身已经有清楚的 01 / 02 分区，不再重复做一块“预览我即将创建什么”的摘要。

### 2.5 个人中心：身份 / 战力 / 基础信息 / 核心属性

**内容角色**：微信身份、游戏角色、总战力、基础信息、9 项核心属性、云端同步状态。

**布局决定**：

- 背景右上角放一个极淡的冰纹图腾（同心环 + 菱形 + 十字轴线），不写数字、不参与交互；
- 不再额外放大标题，身份行直接跟在微标签之后，减少无效高度；
- 身份行：头像、微信名、设置入口；不套全宽深色 hero；
- 战力是页面的主视觉：一个大号 mono 数字，不再在下方重复游戏昵称 / 性别 / 资料状态；
- 基础信息是一块开放数据表：游戏昵称、性别、所属区服、所属同盟；组织信息不再单独做卡片；
- 核心属性是第二块数据表：步兵生命、步兵防御、弓兵攻击、弓兵破坏、骑兵攻击、骑兵破坏、集结伤害加成、集结伤害减免、出征兵力上限；
- 基础信息与核心属性的标题都显示中文 + 左侧英文微标签，右侧各有一个「编辑 →」；
- 两个编辑入口进入同一个 `pages/game-profile-edit/game-profile-edit?section=basic|core`，页面只渲染对应分区；保存时仍提交完整基础信息 + 核心属性；
- 百分比字段显示数字 + `%`，兵力上限显示整数；未填写显示 `—`；
- 同步状态只作为小状态点，不占用主视觉；
- 宽屏时战力在左，基础信息 + 核心属性在右纵向排列。

### 2.6 底部导航：四个一级入口

| Tab | 一级任务 | 当前内容 |
|---|---|---|
| **总览** | 看同盟全员属性汇总 | 空白状态 |
| **拜访** | 看同盟成员列表，进入对方个人中心参考养成 | 空白状态 |
| **同盟** | 创建、加入与管理同盟 | 空白状态 |
| **我的** | 当前个人中心 | 已有完整页面 |

- 登录、微信资料、角色初始化是流程页，不进 tabBar；资料未完成时不得出现底部导航。
- 四个 tab 页面都使用 `custom-tab-bar`，不是微信原生 tabBar 默认样式。
- 没有同盟时，总览 / 拜访展示有设计感的空状态，不伪造数据；主操作引导仍在「同盟」。
- 当前登录完成后落到「我的」，因为它是唯一已有真实内容的 tab。

### 2.7 设置页：账号 / 应用 / 数据 / 会话

- 个人中心身份行右侧（原「编辑 →」位置）放「设置 →」，进入 `/pages/settings/settings`。
- 设置页使用**统一列表结构**，方便后续继续加行：
  - 分组：ACCOUNT / APPLICATION / DATA / SESSION；
  - 每组顶部 1rpx 墨线 + mono kicker；
  - 行与行之间 1rpx 墨线；
  - 所有普通行统一 `104rpx` 最小高度；
  - 行内左侧 label，右侧 value / 小按钮 / 箭头。
- 分组内需要补充解释时，使用行下方的 `.settings-note`，不把说明塞进行高里。
- ACCOUNT：微信身份、微信资料（头像与昵称 →）。
- APPLICATION：版本。
- DATA：注销账户 + 行下方清空范围说明；右侧小「注销」按钮。
- SESSION：退出登录 + 行下方“不会解除微信身份或删除云端档案”说明。
- 注销账户和退出登录都是**灰色 / 墨色**，不使用红色文字；危险语义由文案和二次确认承担。
- 注销账户会清空微信资料、角色资料与头像，成功后回到总览；退出登录只退出本机状态，不删除云端档案。
- 退出后回到总览；再次进入「我的」时未登录会进入登录页。

### 2.8 空状态

- 空白页不是一块白屏，也不是错误页。
- 每页保留页面头（eyebrow / 大标题 / 副标题）+ 一块开放空状态：菱形线框 + 中心点 + mono kicker + 标题 + 一句说明。
- 空状态颜色使用深青 / 墨色 / muted，不使用红色；不出现“错误”“失败”语义。
- 空状态不放假按钮。功能未开放时只说明“后续开放”，不做一个点了没反应的 CTA。

## 三、色彩

所有 token 定义在 `app.wxss` 的 `page` 上。**页面不得直接出现新的十六进制色值。**

### 3.1 背景与纸面

| token | 值 | 用途 |
|---|---|---|
| `--sb-bg` | `#f3f1ea` | 暖纸页面底色 |
| `--sb-surface` | `#fbfaf6` | 表单 / 数据纸面 |
| `--sb-surface-soft` | `#ece9e0` | 头像底、内嵌块 |
| `--sb-surface-muted` | `#e4e0d6` | 更深的纸面 |
| `--sb-control-bg` | `#f6f3ec` | 输入槽 |

### 3.2 文字

| token | 值 | 用途 |
|---|---|---|
| `--sb-text` | `#141b21` | 正文 |
| `--sb-text-strong` | `#080d12` | 大标题、主数字 |
| `--sb-text-muted` | `#6d767f` | 副标题、说明 |
| `--sb-text-faint` | `#9ba1a7` | 微标签、脚注 |
| `--sb-action-bg` | `#111820` | 主按钮墨黑 |
| `--sb-action-text` | `#f8f7f2` | 主按钮文字 |

### 3.3 强调与状态

| token | 值 | 用途 |
|---|---|---|
| `--sb-accent` | `#255f59` | 深青：编号、进度、焦点、链接 |
| `--sb-accent-strong` | `#184743` | 强调文字 / 数据值 |
| `--sb-accent-soft` | `#e2eeec` | 选中浅底 |
| `--sb-danger` | `#c24d41` | 错误 |
| `--sb-danger-soft` | `#fbece8` | 错误浅底 |
| `--sb-danger-line` | `#eac7bf` | 错误边线 |
| `--sb-success` | `#2e7d5b` | 成功 / 同步状态点 |

规则：

- 深青是唯一强调色，不做蓝紫渐变、彩虹描边、发光字。
- 主操作使用墨黑，不把深青铺成大按钮；深青只做“系统指示”。
- 页面背景暖纸，不使用纯白满屏、渐变背景或纹理图片。
- 错误色只给错误；普通“未设置 / 暂未开放”用墨灰。

## 四、圆角、边线与阴影

### 4.1 圆角

| token | 值 | 用途 |
|---|---|---|
| `--sb-radius-card` | `20rpx` | 表单纸面、数据表 |
| `--sb-radius-control` | `12rpx` | 输入框、按钮 |
| `--sb-radius-tag` | `6rpx` | 步骤徽标、小标签 |
| `--sb-radius-pill` | `999rpx` | 头像、状态点、胶囊 |

- 不使用大圆角卡片语言；圆角接近直角，保持编辑感。
- 头肩剪影属于 CSS 插画轮廓，不受容器圆角限制。

### 4.2 边线与阴影

- 页面主要分隔：`1rpx solid var(--sb-line)`；重要顶部边界可用 `3rpx` 墨线或深青线。
- 纸面只有 1rpx 边线，**无 drop shadow、无玻璃模糊、无大范围发光**。
- 输入 focus 使用 3rpx 深青 soft 外环，属于状态，不是装饰。
- 状态点可以带极小的阴影光晕（仅头像 / 状态），不用于卡片。

## 五、排版

### 5.1 字体

- 全部使用系统无衬线：`-apple-system / SF Pro Display / Segoe UI / Inter / PingFang SC`。
- 技术标签、编号、数字使用 `--sb-font-mono`（SF Mono / Roboto Mono / IBM Plex Mono）。
- 不加载网络字体，不使用宋体；中文和英文都在同一无衬线系统里。
- 本版不依赖独立图标字体，界面只用少量 CSS 点、线和文字。

### 5.2 字号阶梯

| 字号 | 用途 |
|---|---|
| `82rpx` | 宽屏登录主标题 |
| `68rpx` | 手机登录主标题 |
| `58rpx` | 页面主标题 |
| `50rpx` | 个人中心微信名 |
| `88rpx` | 战力主数字 |
| `32rpx` | 输入值、状态标题 |
| `30rpx` | 正文、按钮 |
| `27–28rpx` | 字段名、卡片标题、次要按钮 |
| `24–26rpx` | 说明、帮助、错误、副标题 |
| `16–20rpx` | 仅技术标签、编号、微文案 |

- 正文不小于 `24rpx`，输入 `32rpx`。
- 字重只用 `400 / 500 / 600`，不使用 700 及以上。
- 标题行高 `1.1–1.18`；正文 `1.5–1.7`。

### 5.3 微标签与数字

- `STEP 01`、`TOTAL POWER`、`INITIALIZATION` 等微标签：mono、`16–20rpx`、字距 `2–3rpx`、淡墨或深青。
- 战力、编号、同步状态使用 mono；战力使用 `tabular-nums`。
- 英文只放在技术标签和分区标题上；主体内容保持中文。

## 六、布局骨架

### 6.1 页面通用

- 内容最大宽度 `720px`，左右边距 `32rpx`，顶部由页面头控制，底部 `44–48rpx + safe-area`。
- 页面头：微标签 / 编号 + 大标题 + 副标题 + 进度线（仅两步流程）。
- 每个页面只允许一个主视觉：登录大标题、资料头像、初始化表单、个人中心战力数字。
- 卡片仅用于“需要输入或读数据的纸面”，不用卡片包身份、标题、进度或说明。

### 6.2 页面头

```
eyebrow (mono cobalt)                        eyebrow-note (faint)
────────────────────────────────────────────────────────────
STEP 02 或 01 / 02
[progress line]
大标题（58rpx / 600 / ink）
副标题（27rpx / muted / max 620rpx）
```

- 页面头与纸面左对齐。
- 标题不居中；全部左对齐，形成编辑式阅读方向。
- 进度线只用于两步流程，不放入登录页。

### 6.3 宽屏

| 断点 | 变化 |
|---|---|
| `< 700px` | 登录单列；标题、认证清单、页脚纵向 |
| `700–759px` | 登录改为左右两列（文案 / 认证清单） |
| `≥ 760px` | 资料页身份 + 表单左右分栏；个人中心战力与基础信息 / 核心属性左右分栏；初始化保持单列表单 |
| 桌面 | 内容最大 720px（登录 900px）居中，不铺满全屏 |

- 页面不横向滚动；手机始终单列。
- 宽屏分栏是“内容本来就成组”的结果，不是为了填满屏幕。

### 6.4 自定义导航栏

- 四个 tab 页（总览 / 拜访 / 同盟 / 我的）使用 `navigationStyle: "custom"`，不再使用微信原生导航栏。
- 由 `components/nav-bar/` 绘制：
  - 状态栏高度 + 胶囊按钮所在导航高度；
  - 暖纸底 `#f3f1ea`，居中 30rpx 标题；
  - 不画返回 / 首页按钮，避免和胶囊、底部导航重复。
- 非 tab 页（登录、微信资料、初始化）继续使用原生导航栏；仍调用 `wx.hideHomeButton()` 隐藏原生首页按钮。
- 自定义导航栏的根本目的不是换皮，而是消除原生导航栏在 tab 切换时先绘制白色首帧的问题。

### 6.5 底部导航

- 固定底部、全宽、暖纸底 `#f3f1ea`，顶部 1rpx 墨线；无阴影、无玻璃、无圆角浮岛。
- 内容最大宽度 720px 居中；高度 116rpx，另加 `env(safe-area-inset-bottom)` 安全区。
- 四个 tab 等分：总览 / 拜访 / 同盟 / 我的。
- 每个 tab 三行：2rpx 选中短线、23rpx 中文标签、13rpx mono 英文标签。
- 选中：短线深青、中文墨黑 600、英文深青；未选中：中文 muted、英文 faint。
- 不在 tabBar 放图标、emoji、库存图标或大圆角选中胶囊。
- 所有 tab 页面底部留 `176rpx + safe-area`，保证内容不被 tabBar 覆盖。
- tab 页面切换使用 `wx.switchTab`，不使用 `wx.navigateTo` / `wx.reLaunch`；登录 / 初始化等非 tab 页仍使用 `wx.reLaunch`。

## 七、组件形态

### 7.1 页面头与步骤

- `.page-head`：上边距 48rpx，下边距 30rpx，入场 `sb-rise` 0.52s。
- `.eyebrow`：mono 20rpx、深青、字距 3rpx。
- `.page-title`：58rpx、600、ink、行高 1.15。
- `.page-subtitle`：27rpx、muted、行高 1.65。
- `.step-badge`：48×40rpx、6rpx 圆角、1rpx 边、mono 20rpx。
- `.step-track`：2rpx 线，填充用深青；第 1 步 50%、第 2 步 100%；scaleX 入场。

### 7.2 身份舞台（identity stage）

- 用于微信资料页头像：开放布局，`padding: 28rpx 0`，上下 1rpx 墨线。
- 顶部 `WECHAT IDENTITY` mono 标签；下方是左右结构：左侧 148rpx 圆角方形头像（28rpx 圆角），右侧标题、操作提示和格式说明。
- 头像无边框、`--sb-surface-soft` 底；无大阴影，不使用虚线 / 蚂蚁线。

- 内圈 72s、菱形 96s 极慢反向旋转；只作为空间纹理，不表达进度、等级或编号。

- 图腾只在个人中心出现；登录页保留大号 `00` 作为纯视觉锚点（没有业务编号含义，但用户确认保留）。其他页面不复制。
### 7.7 战力主视觉

- 个人中心独立块：顶部和底部都不设粗墨线，由下方基础信息 section 的顶部线承担唯一分隔。
- `TOTAL POWER / 当前总战力` mono 18rpx；
- 数字 88rpx mono，`tabular-nums`，墨黑；
- 数字首次出现时从 0 缓动计数到真实值：900ms、ease-out、约 32ms 更新一次；值未变化时下拉刷新不重复播放；
- 战力区下方不再放游戏昵称 / 性别 / 资料状态 meta；这些信息进入基础信息表。
- 这是页面唯一的超大数字；其他数字不得抢主视觉。

### 7.8 基础信息与核心属性

- 基础信息：开放数据表，两列网格 + 1rpx 分隔线；游戏昵称、性别、所属区服、所属同盟为两列。
- 核心属性：与基础信息连成一个连续信息板，01 / 02 编号之间不再留空档；9 项属性两列排布，最后一项「出征兵力上限」整行。
- 单元格：22rpx faint 标签 + 26rpx 墨色值；核心属性值使用 mono 29rpx，百分比单位与数字同基线、同 mono 字体、19rpx muted 展示，避免小字号无衬线 `%` 像附属符号。
- 未填写显示 `—`，不显示 0；不把组织信息做成单独卡片。
- 基础信息「编辑 →」打开 `game-profile-edit?section=basic`，核心属性「编辑 →」打开 `?section=core`；编辑页只显示对应区块。
- 编辑页保存时提交完整基础信息 + 核心属性，百分比输入使用数字键盘 + `%` 后缀，兵力上限为整数；保存后回个人中心并静默刷新。

### 7.9 状态

- 加载：状态卡（纸面）或整页 `state-screen`；spinner 42–44rpx、深青顶部。
- 错误：圆形 `!` + 32rpx 标题 + 26rpx 说明 + 次按钮。
- 已同步 / 成功：7rpx 绿色点 + mono 标签。
- 微信资料未完善：深青左线的 inline banner，不用红色。
- 头像失败：清空图片并提示点击重设；不显示破图。

### 7.10 自定义 tabBar

- 组件目录：`custom-tab-bar/`；`app.json` 的 `tabBar.custom = true`。
- 组件自行读取 `getCurrentPages()` 与页面 `onShow` 同步选中态；不能只靠点击时改 data，否则返回页面会错位。
- 点击当前 tab 不重复入栈；点击其他 tab 用 `wx.switchTab`。
- 页面切换动画由微信原生处理；tabBar 自身不加滑动 / 弹跳 / 缩放。
- 安全区由 `.tabbar` 的 `padding-bottom: env(safe-area-inset-bottom)` 处理。

### 7.12 启动与登录入口

- 启动页是 `pages/overview/overview`，启动不调用云函数、不显示登录页。
- 总览 / 拜访 / 同盟属于账号数据页，未登录时只显示登录后读取的说明，不伪造内容。
- 用户点击「我的」时判断登录状态；未登录直接 `reLaunch` 到 `pages/index/index`。
- 登录页保留「先逛逛，不登录」，可返回总览，不是死路。
- 登录按钮是用户主动动作；登录成功后短 loading 直接切换个人中心或角色初始化。
- 登录后不自动进入微信资料页；头像昵称保持可选。
- 注销 / 退出后回到总览；再次进入「我的」时再判断登录。

### 7.12b Tab 切换微动效

- 微信原生 `switchTab` 转场不可定制，不做全屏伪滑动、遮罩或延迟路由。
- 每次 tab 页 `onShow`，根节点执行 280ms 淡入 + 8rpx 上浮，缓动 `--sb-ease`；
- 同页面的 `page-head` / `profile-head` / `power-panel` 不再各自上浮，避免二次动画；
- 自定义 tabBar 选中短线：`opacity 0 → 1`、`scaleX(0.4) → 1`，200ms；标签 / 英文颜色同步过渡；
- 非 tab 页面保留微信原生推入转场，只保留内容自身的短入场；
- `prefers-reduced-motion` 下全部关闭。

### 7.13 个人中心下拉刷新

- 个人中心不再使用原生 `enablePullDownRefresh`，改用页面内 `scroll-view` 的 `refresher-enabled`。
- `refresher-background="#f3f1ea"`，刷新区域和页面同为暖纸色；不使用白底。
- `refresher-triggered` 由页面 `refreshing` 控制；刷新结束后手动收起。
- `loadProfile()` 增加 in-flight 请求锁，同一时间只允许一个 `bootstrap`；一次下拉不会触发两次请求。
- 页面外再包一层 `page-meta page-style="background-color: #f3f1ea;"`，兜底 WebView 首帧。

### 7.14 自定义导航栏

- 目录：`components/nav-bar/`。
- 高度计算：`statusBarHeight` + `navBarHeight`，后者由胶囊按钮的 `top / height` 推导，兜底 44px。
- 组件结构：固定顶部 `.nav` + 文档流 `.nav__spacer`；标题居中，避开右侧胶囊。
- 标题 30rpx / 500；背景和页面同为暖纸，不加底部分隔线。
- tab 页 `.json` 设置 `navigationStyle: "custom"` 并注册 `nav-bar`；非 tab 页不注册。
- 自定义导航栏不处理返回；tab 页没有返回层级。

### 7.11 空状态

- `.empty-panel`：上下 1rpx 线，开放布局，不套白卡。
- `.empty-glyph`：72rpx 菱形线框 + 中心深青点，不使用图标库。
- `.empty-kicker`：mono 18rpx 深青；`.empty-title` 36rpx；`.empty-copy` 25rpx muted，最大 580rpx。
- 空状态只在 tab 空白页使用；已有数据页面不要用“空状态”伪装加载失败。

## 八、动效

| 动效 | 用法 | 时长 |
|---|---|---|
| `sb-rise` | 页面头、纸面、注释条入场：上移 16rpx + 淡入 | 0.52–0.58s |
| `step-fill` | 进度线从左生长 | 0.8s，延迟 0.2s |
| `login-in` | 登录页文案、认证清单、页脚错峰入场 | 0.55–0.65s |
| `power-count` | 战力数字从 0 到真实值的短计数 | 900ms，ease-out |
| `marker-pulse` | 验证中的信号点轻微呼吸 | 2.4s 循环 |
| 颜色 / 边框 | 输入 focus、按钮按压 | 0.16–0.18s |

- **动效方向固定为“从左到右 / 自下而上”**，不左右乱飞。
- 不用持续旋转、粒子、背景光斑、霓虹扫描；登录页只有一个呼吸信号点和一个 spinner。
- 战力计数是唯一由 JS 驱动的数字动效；除数字本身外，不用 JS 逐帧驱动页面。
- 所有入场使用 `transform + opacity`，不改变布局。
- `prefers-reduced-motion: reduce` 下关闭入场、进度生长、呼吸和 spinner 之外的动画。

## 九、可访问性与工程约束

- 正文 ≥24rpx，输入 32rpx，主按钮 96rpx，次按钮 88rpx，文本链接最小 68rpx。
- 深青文字仅用于标签 / 链接，不用于长正文；正文使用墨色。
- 纸面与背景的对比必须足够；输入 focus 有明确深青外环，不依赖颜色变化单一指示。
- 小程序没有 DOM：不使用 GSAP / Framer Motion / Rive Web；CSS 动画优先。
- 本版不引入 UI 库、网络字体、图片、Lottie、Canvas；未来只在明确需要时加。
- 非 tab 页的原生导航栏为暖纸底墨色字（`#f3f1ea` / black），与页面纸面连成一体；tab 页使用自定义 `nav-bar`。
- 非 tab 流程页在 `onShow` 调用 `wx.hideHomeButton()`；但设置页是带返回箭头的二级页，不再调用，避免进入动画期间重排原生导航栏。tab 页没有原生导航，不需要调用。
- 页面最大宽度：普通页 720px，登录页 900px；不使用多栏填满桌面。
- tab 页使用自定义导航栏，原生导航栏不再参与 tab 切换；非 tab 页仍显式设置导航 / 页面背景，不能只依赖 `app.json` 的 window 配置继承。
- 页面外层背景做三层兜底，避免新页面 WebView 首帧白底：
  1. `app.wxss` 的 `page` 与 `.page` 显式 `background-color: #f3f1ea`；
  2. `app.json` / 页面 JSON 设置 `backgroundColor`、`backgroundColorTop`、`backgroundColorBottom`；
  3. `app.js` 在 `onLaunch` / `onShow` 调用 `wx.setBackgroundColor()` 统一窗口底色。
- 上述兜底只能解决页面 WebView 首帧白底；tab 页最终通过自定义导航栏彻底移除原生导航栏白条。

## 十、禁令

1. 把页面做成“背景 + 居中大卡 + 三个字段”的通用模板。

6. 使用宋体、网络字体、700 以上字重。
7. 一个页面出现两个墨黑主按钮或两个深青主视觉。
8. 让动画持续、铺满、影响点击或延迟内容出现。
9. 用红色表达普通“未设置 / 暂未开放 / 暂无数据”。
10. 第二套微信资料编辑 UI；编辑只走 `wechat-profile?mode=edit`。
11. 把截图或其他二进制资源放回 `docs/`。

## 十二、改动流程
