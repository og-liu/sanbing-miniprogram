# 云函数接口文档

> 本文是本项目**所有云函数的统一接口契约**，面向当前开发和后续维护。
> 云函数的新增、动作扩展、字段变化和错误码调整都在本文件内追加，**不再按“第几期”拆文档，也不另建第二份 API 文档**。
>
> 当前实现使用微信云开发，不使用自建 HTTP API，不需要 AppSecret、Authorization Header 或自建 Session。
> 环境：`sanbing-prod`（`cloud1-d6gldy1dwe50f247a`）
>
> 维护规则：**先更新接口文档，再改云函数或客户端调用代码**；新增云函数时，先在本文件“云函数索引”登记，再在正文补章节。

## 一、文档约定

- 一个云函数一个正文章节；章节内按“动作 → 请求 → 校验 → 响应 → 错误码 → 数据”组织。
- 动作名使用 camelCase；新增动作必须加入云函数的动作白名单。
- 所有示例只使用测试值，不写真实用户昵称、OpenID、UnionID、fileID 或签名 URL。
- 接口变化属于可追溯变更；涉及字段、错误码、权限或数据集合时，同步更新《开发日志》。
- 客户端接口封装统一在 `services/api.js`；页面不直接拼 `wx.cloud.callFunction`。

## 二、调用方式

小程序端统一通过 `services/api.js` 调用云函数：

```js
// services/api.js 内部封装的核心调用
const result = await wx.cloud.callFunction({
  name: config.cloudFunctionName,
  data: {
    action: 'bootstrap'
  }
})
```

`config/index.js` 当前配置：

| 配置项 | 值 |
|---|---|
| 云环境 ID | `cloud1-d6gldy1dwe50f247a` |
| 云函数名 | `sanbingAccount` |
| 头像大小上限 | 500KB |

云函数从可信调用上下文识别用户：

```js
const context = cloud.getWXContext()
const openid = context.OPENID
```

- 不接受前端传入的 OpenID、UnionID 或用户 ID 作为身份凭证。
- 不需要 Authorization Header、Session Token 或 AppSecret。
- 客户端调用身份由微信云开发认证。

## 三、云函数索引

| 云函数 | 状态 | 用途 | 动作 | 主要数据 |
|---|---|---|---|---|
| `sanbingAccount` | Active | 账号、游戏角色与核心属性、微信资料、头像与档案重置 | `bootstrap`、`saveGameProfile`、`updateGameProfile`、`saveWechatProfile`、`resetProfile` | `sanbing_users`、`sanbing_game_profiles`、`avatars/` |

## 四、统一响应

成功：

```json
{
  "ok": true,
  "data": {}
}
```

业务失败：

```json
{
  "ok": false,
  "error": {
    "code": "INVALID_NICKNAME",
    "message": "游戏昵称不能为空"
  }
}
```

未预料的云端异常统一归一化为：

```json
{
  "ok": false,
  "error": {
    "code": "INTERNAL_ERROR",
    "message": "云端服务暂时不可用，请稍后重试"
  }
}
```

内部异常细节只写云函数日志，不返回给客户端。

客户端 `services/api.js` 的行为：

- `ok: true` → 返回 `data`；
- `ok: false` → 抛出带 `code` 的 `CloudError`；
- 网络失败、函数不存在、超时 → 归一化为 `CLOUD_CALL_FAILED` 等客户端错误；
- `code === 'UNAUTHORIZED'` 由页面决定重新进入登录流程。

## 五、通用约束

- 所有业务读写通过云函数的管理端权限执行；客户端不直接读写业务集合或上传头像。
- 身份只来自 `getWXContext().OPENID`，不能用请求参数覆盖。
- 服务端必须校验所有可写字段；前端校验只负责体验，不构成安全边界。
- 云函数响应不返回 OpenID、UnionID、数据库内部 `_id`、头像 fileID、session_key。
- 时间字段统一使用 ISO 8601 字符串；头像展示 URL 为短时签名 URL，刷新时重新生成。
- 未知 `action` 必须返回 `INVALID_ACTION`，不执行任何写操作。
- 任何新增动作都必须考虑：身份、输入校验、权限、幂等性、错误码和返回体。

## 六、`sanbingAccount`

账号、角色资料和微信资料的统一云函数。角色初始化是幂等边界：同一微信身份重复初始化不会覆盖旧资料。

### 6.1 动作总览

| 动作 | 用途 | 是否写数据 | 主要入参 |
|---|---|---|---|
| `bootstrap` | 识别微信身份，读取或创建账号，返回账号与角色 bundle | 首次调用可能创建用户 | 无 |
| `saveGameProfile` | 首次初始化游戏角色 | 是 | `gameNickname`、`totalPower`、`gender` |
| `updateGameProfile` | 修改游戏身份、战力和核心属性 | 是 | `gameNickname`、`totalPower`、`gender`、`attributes` |
| `saveWechatProfile` | 保存用户主动提供的微信昵称和头像 | 是 | `nickname`、可选 `avatarBase64` |
| `resetProfile` | 清空当前微信身份的账号、角色资料、头像与云端档案（客户端「注销账户」） | 是（删除） | 无 |

### 6.2 `bootstrap`

用于冷启动、初始化页守卫生效判断和个人中心刷新。

请求：

```json
{
  "action": "bootstrap"
}
```

行为：

1. 从 `getWXContext().OPENID` 获取微信身份。
2. 使用确定性的内部用户 ID 查找或创建账号。
3. 读取角色资料。
4. 如果存在头像，生成云存储临时 URL。
5. 返回用户、角色资料和初始化状态。

未初始化用户成功响应示例：

```json
{
  "ok": true,
  "data": {
    "user": {
      "id": "平台随机公开 ID",
      "wechat": {
        "nickname": null,
        "avatarUrl": null,
        "hasAvatar": false,
        "isComplete": false
      },
      "createdAt": "2026-11-11T08:13:30.108Z",
      "updatedAt": "2026-11-11T08:13:30.108Z"
    },
    "gameProfile": null,
    "initialized": false
  }
}
```

已初始化用户成功响应示例：

```json
{
  "ok": true,
  "data": {
    "user": {
      "id": "平台随机公开 ID",
      "wechat": {
        "nickname": "示例用户",
        "avatarUrl": "云存储临时图片 URL",
        "hasAvatar": true,
        "isComplete": true
      },
      "createdAt": "2026-11-11T08:13:30.108Z",
      "updatedAt": "2026-11-11T08:20:00.000Z"
    },
    "gameProfile": {
      "gameNickname": "示例角色",
      "totalPower": 123456,
      "gender": "male",
      "organization": {
        "server": "unjoined",
        "guild": "unjoined",
        "guildRank": "none"
      },
      "attributes": {
        "infantryHp": 12.5,
        "infantryDefense": null,
        "archerAttack": 8,
        "archerDestruction": null,
        "cavalryAttack": null,
        "cavalryDestruction": null,
        "rallyDamageBonus": null,
        "rallyDamageReduction": null,
        "marchCapacity": 120000
      },
      "isInitialized": true,
      "createdAt": "2026-11-11T08:14:15.025Z",
      "updatedAt": "2026-11-11T08:14:15.025Z"
    },
    "initialized": true
  }
}
```

说明：

- 不返回 OpenID、UnionID、数据库文档 `_id`、头像 fileID。
- `avatarUrl` 是带有效期的临时链接，每次刷新资料时重新生成。
- `hasAvatar` 表示服务端是否保存了头像；即使临时 URL 生成失败，也能区分“未设置头像”和“头像加载失败”。
- `bootstrap` 对同一身份必须可重复调用，不重复创建账号；首次创建后保持稳定。

### 6.3 `saveGameProfile`

首次初始化游戏角色资料。

请求：

```json
{
  "action": "saveGameProfile",
  "gameNickname": "示例角色",
  "totalPower": 123456,
  "gender": "male"
}
```

校验：

- `gameNickname`：非空字符串，去除首尾空白后最多 30 个 Unicode 字符，不允许控制字符。
- `totalPower`：JSON number，必须是 `0` 到 `999999999999` 之间的安全整数。
- `gender`：只能是 `male` / `female` / `secret`。
- 不接受组织信息、用户 ID 等额外字段作为资料输入。

成功响应 `data` 与 `bootstrap` 的已初始化响应相同。

- 角色资料和账号 `profileInitialized` 标记通过云数据库事务写入。
- 已完成初始化时返回 `PROFILE_ALREADY_INITIALIZED`，不覆盖原有资料。
- 并发写入由事务保证不会出现“只写了一半”的状态。

### 6.4 `updateGameProfile`

修改已初始化角色的基础信息、总战力和核心属性。组织信息此阶段仍由云端保留默认值，不在本动作中修改。

请求：

```json
{
  "action": "updateGameProfile",
  "gameNickname": "示例角色",
  "totalPower": 123456,
  "gender": "male",
  "attributes": {
    "infantryHp": 12.5,
    "infantryDefense": 10,
    "archerAttack": 8,
    "archerDestruction": null,
    "cavalryAttack": null,
    "cavalryDestruction": null,
    "rallyDamageBonus": 3.25,
    "rallyDamageReduction": null,
    "marchCapacity": 120000
  }
}
```

核心属性字段：

| 字段 | 中文 | 类型 | 单位 / 范围 |
|---|---|---|---|
| `infantryHp` | 步兵生命 | number / null | %；0–999999.99，最多两位小数 |
| `infantryDefense` | 步兵防御 | number / null | 同上 |
| `archerAttack` | 弓兵攻击 | number / null | 同上 |
| `archerDestruction` | 弓兵破坏 | number / null | 同上 |
| `cavalryAttack` | 骑兵攻击 | number / null | 同上 |
| `cavalryDestruction` | 骑兵破坏 | number / null | 同上 |
| `rallyDamageBonus` | 集结伤害加成 | number / null | 同上 |
| `rallyDamageReduction` | 集结伤害减免 | number / null | 同上 |
| `marchCapacity` | 出征兵力上限 | number / null | 非负整数；0–999999999 |

校验：

- 只有已初始化角色可以更新；否则返回 `PROFILE_NOT_INITIALIZED`。
- `gameNickname`、`totalPower`、`gender` 校验同 `saveGameProfile`。
- `attributes` 必须存在；未知字段忽略，上述字段缺省 / 空值保存为 `null`。
- 百分比字段只接受最多两位小数的非负 number；客户端负责把输入字符串转成 number。
- 不修改 `organization`、`isInitialized`、创建时间等字段。

成功响应 `data` 与 `bootstrap` 的已初始化响应相同。

### 6.5 `saveWechatProfile`

保存用户主动提供的微信头像昵称。

请求：

```json
{
  "action": "saveWechatProfile",
  "nickname": "示例用户",
  "avatarBase64": "可选，JPG/PNG/WebP 裸 Base64"
}
```

- `nickname` 必填，最多 30 个 Unicode 字符。
- `avatarBase64` 可选；省略时保留原头像，仅更新昵称。
- Base64 解码后不能超过 500KB。
- 服务端通过文件头识别实际图片类型，不信任文件名或 MIME 声明。
- 云函数校验后上传到：

```text
avatars/<publicId>/<timestamp>-<random>.<ext>
```

- 更新成功后会删除旧头像文件；更新失败则清理刚上传的新文件。
- 成功响应 `data` 与 `bootstrap` 在对应初始化状态下的响应相同（未初始化用户不会凭空产生角色资料）。

### 6.6 `resetProfile`

重置当前微信身份对应的全部档案，用于用户主动重新开始。

请求：

```json
{
  "action": "resetProfile"
}
```

行为：

1. 从 `getWXContext().OPENID` 推导用户 ID，不接受前端传入身份；
2. 删除 `sanbing_game_profiles` 对应用户文档；
3. 删除 `sanbing_users` 对应用户文档；
4. 尝试删除该用户当前头像文件；如果头像文件不存在或清理失败，不阻塞数据库档案清空，只记录日志；
5. 返回：

```json
{
  "ok": true,
  "data": {
    "reset": true
  }
}
```

边界：

- 只影响当前微信身份，不能清空其他用户；
- 重复调用是幂等的：没有用户 / 角色文档时仍返回成功；
- 这是不可恢复操作，客户端必须先做二次确认；
- 不负责清本地偏好；客户端在成功后清理 `sanbing.entry.completed.v1`、`sanbing.onboarding.wechatSkipped.v1` 与 `sanbing.auth.signedOut.v1`，回到首次进入状态；
- 不删除云环境、集合结构、其他用户或其它头像目录。

### 6.7 数据枚举

性别 `gender`：

| 值 | 含义 |
|---|---|
| `male` | 男 |
| `female` | 女 |
| `secret` | 保密 |

组织状态：

| 字段 | 当前值 | 当前前端文案 |
|---|---|---|
| `organization.server` | `unjoined` | 暂未加入任何区服 |
| `organization.guild` | `unjoined` | 暂未加入任何同盟 |
| `organization.guildRank` | `none` | 暂无阶级 |

当前只写入上述默认值；其它组织状态为后续功能预留，新增枚举时必须同步服务端校验、前端映射和本文档。

### 6.8 错误码

| code | 场景 |
|---|---|
| `UNAUTHORIZED` | 云函数上下文缺少可信 OPENID |
| `INVALID_BODY` | 请求体格式错误 |
| `INVALID_ACTION` | 未知 action |
| `INVALID_NICKNAME` | 昵称为空、过长或包含控制字符 |
| `INVALID_TOTAL_POWER` | 战力不是非负整数或超出范围 |
| `INVALID_GENDER` | 性别枚举非法 |
| `PROFILE_ALREADY_INITIALIZED` | 重复提交初始化 |
| `PROFILE_NOT_INITIALIZED` | 更新已初始化角色资料时找不到角色 |
| `INVALID_CORE_ATTRIBUTE` | 核心属性不是合法数值 / 小数 / 整数 |
| `INVALID_AVATAR` | 头像不是合法 JPG/PNG/WebP |
| `AVATAR_TOO_LARGE` | 头像超过 500KB |
| `INTERNAL_ERROR` | 未预料的云端错误 |

`UNAUTHORIZED`、`INVALID_BODY`、`INVALID_ACTION`、`INTERNAL_ERROR` 是通用错误语义；其余为 `sanbingAccount` 当前动作专属。

### 6.9 云端数据集合

#### `sanbing_users`

| 字段 | 说明 |
|---|---|
| `_id` | 服务端派生的内部用户 ID，不返回客户端 |
| `openid` | 微信 OpenID，仅服务端可见 |
| `unionid` | 可选，仅服务端可见 |
| `publicId` | 随机公开用户 ID |
| `wechatNickname` | 微信昵称 |
| `avatarFileId` | 云存储 fileID，不返回客户端 |
| `avatarUpdatedAt` | 头像更新时间 |
| `profileInitialized` | 角色是否已初始化（事务锁标记） |
| `createdAt` / `updatedAt` | ISO 时间戳 |

#### `sanbing_game_profiles`

| 字段 | 说明 |
|---|---|
| `_id` | 与内部用户 ID 一致 |
| `gameNickname` | 游戏昵称 |
| `totalPower` | 当前总战力 |
| `gender` | `male` / `female` / `secret` |
| `organization` | 默认组织状态对象 |
| `attributes` | 9 项核心属性；数值或 `null`，百分比字段不带 `%` 存储 |
| `isInitialized` | 固定为 `true` |
| `createdAt` / `updatedAt` | ISO 时间戳 |

### 6.10 权限与部署

- 所有业务读写通过云函数以管理端权限执行。
- 客户端不直接访问上述集合；实测云函数创建的文档对客户端直接查询不可见。
- 上线前把两个集合的简易权限设为 **仅管理员可读写**，避免已登录客户端直接写入垃圾文档。
- 头像文件保存在云存储，客户端不持有 fileID；展示使用云函数短时签名 URL。
- 云函数当前运行时为 `Nodejs16.13`，超时 3 秒；正式运营前在控制台提高到 20 秒。
- 云函数由 `cloudfunctionRoot: "cloudfunctions/"` 管理，独立部署，不进入小程序包。

## 七、新增云函数或动作的维护清单

以后要加新云函数（例如 `sanbingBattleReport`），按以下顺序做，并在本文件内追加内容：

1. **登记索引**：在“云函数索引”表格新增一行，写清用途、动作和主要数据。
2. **新增正文**：按“动作总览 → 请求 → 校验 → 响应 → 错误码 → 数据集合 → 权限”写章节。
3. **实现服务端**：只信任 `getWXContext()`；动作加入白名单；写操作必须校验并保持幂等。
4. **更新客户端**：在 `services/` 增加语义化方法，底层仍通过 `services/api.js` 调用，不直接拼云函数名。
5. **补测试**：优先覆盖纯校验、身份边界、错误码和幂等分支；网络 / 页面交互另做联调。
6. **同步权限**：新集合设置管理员权限；新存储目录确认客户端不可直接写。
7. **更新文档**：本文件、README 的云函数列表、`docs/项目目录结构说明.md` 以及《开发日志》。
8. **不另建** `API2.md`、`接口文档-第二期.md` 之类的分册；本文件即长期唯一入口。
